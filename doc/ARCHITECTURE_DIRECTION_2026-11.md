# AnnualReport · 现状与方向建议（2026-11-03）

> 作者：Claude（Anthropic）· Claude Code 云端会话 · 应仓库所有者要求
> 性质：**建议，未实施**。base：`master` @ `2a70d2e`。

## 1. 这个仓库是什么

- 一套**聊天年度报告前端模板**：`report-2023/`（静态页 + fullPage）与 `report-2024/`（`single` 个人版、`double` 双人版，Vue + Vite，数据集中在 `getData.js`）。
- 历史提交作者为上游作者（SiYuan，MemoTrace 年度报告），许可证 MIT（`LICENSE` 保留原版权声明）。在当前账户下**相当于上游镜像**，尚无定制提交。
- 与所有者的其他项目没有代码依赖。

## 2. 建议的定位（三选一，由所有者决定）

| 选项 | 做法 | 适合 |
|---|---|---|
| A · 保持镜像 | 不改代码，只用来生成自己的年度报告；数据留本机 | 只是偶尔自用 |
| B · 个人定制版 | 新建 `custom/` 或分支，写数据适配器把本机导出的聊天统计转成 `getData.js` 所需结构；页面风格按需改 | 每年做一次、希望更好看 |
| C · 做成通用“年度回看”模板 | 抽象数据契约（JSON Schema），可接所有者其他本地工具的统计（如写作字数、研究与复盘数） | 想把多个项目的年度数据做成一份个人年报 |

**我的建议：B，且 C 只作为远期可能。** 理由：这是一份上游模板，最低成本的价值是“每年一份好看的个人回看”；把它变成通用产品需要持续维护，没有证据表明值得。

## 3. 必须守住的边界

1. **聊天数据与统计结果不进 Git**：`getData.js` 若填入真实昵称、头像、聊天片段或统计，就是私人数据。建议把数据文件改为本机忽略的 `getData.local.js`，仓库只留合成示例。
2. **发布前检查**：上游 README 提供在线预览与二维码；自己的报告如需分享，只发布脱敏后的静态包，不要把含真实数据的构建产物推到公开托管。
3. **许可与署名**：MIT 允许修改与再分发，但需保留原版权声明；定制版在 README 写明基于上游模板。
4. **依赖安全**：`report-2024` 依赖 Node 20 时期的包；若重新构建，先 `npm audit` 并锁定版本，不在公开环境运行未审查的构建脚本。

## 4. 若选择 B 的最小步骤（可交给 Codex）

1. 新建分支，加入 `.gitignore`：`**/getData.local.js`、`**/dist/`。
2. `getData.js` 改为：存在本机文件则读取，否则使用合成示例数据。
3. 写一个小的 Python 或 Node 适配脚本：输入本机聊天统计（CSV/JSON），输出 `getData.local.js` 所需结构；脚本只读本地文件，不联网。
4. 用合成数据构建并截图验收；真实数据只在本机构建与预览。
